# Bounded county renderer benchmarks

The county prototype accepts an explicit policy file. Its default remains one full county per detailed PDF. State, county, and area names drive actual folder paths, PDF titles, headings, and bookmark checks. Selected policy bytes enter the recipe; unrelated county configurations do not. Every selected source-named way still needs a visible label, including bounded larger-scale insets. Existing Bristol artifacts remain unchanged under their original recipes.

The initial additional benchmarks use the existing Rhode Island source set: Census 2025 county boundaries, Geofabrik 2026-10-29 roads, the pinned 2026-10-30 Rhode Island PMTiles, the original incomplete Rhode Island directory, existing fonts, and epoch `1793404800`. The reused directory remains `complete: false`; rerendering does not add missing records or clear any review hold.

Only three Bristol ZIP geometries were cached. One bounded, unsimplified official [Census 2020 TIGERweb layer 84](https://tigerweb.geo.census.gov/arcgis/rest/services/Census2020/tigerWMS_Census2020/MapServer/84?f=pjson) query adds ZCTAs 02892 and 02903 from that same already selected vintage. Its response is 133,681 bytes, SHA-256 `15a1e41af65d9e0bb0d83c1e56bbea49df5ee3110ad3e505b05c2c8ffea6274f`. It is a held build input, not a new upstream release or national cargo. Its release date, review, and advisory/age gates remain unconfirmed. Census ZCTAs are dated statistical approximations, [not current USPS delivery boundaries](https://www.census.gov/programs-surveys/geography/guidance/geo-areas/zctas.html).

Two area policies provide bounded density comparisons: Providence County intersected with 2020 ZCTA 02903, then Washington County intersected with 2020 ZCTA 02892. These are explicitly partial-county benchmark scopes, not a claim that a production county must split or that the whole county is complete. Polygon intersection preserves the county as the maximum group; the original one-to-many county relationship data remains unchanged. Only source-verified ZIP codes appear in names. No population dataset or invented postal coverage is introduced; road density is measured from the selected source.

Each benchmark first runs `tools/prototype_county_map.py --counts-only --policy <selected JSON>` with authenticated inputs. It then renders one area at a time under one CPU and 4 GiB, using the pinned image, no network, read-only source/cache/input mounts, and a fresh output. The selected engineering trials retain 1:25,000 base scale, 190 × 230 mm map frames, 10% overlap, 64 total pages, maximum inset depth 5, source-way/vertex/tile guards, and the shared 10 MB PDF guardrail. These are explicit trial settings, not publisher defaults or phone acceptance evidence.

Record actual elapsed time, cgroup/RSS peak, exit and OOM state, source-way/name counts, base/inset/actual PDF pages, bytes, missing IDs, and actual map-region visual evidence. A page, coverage, or byte failure remains a failure with preserved diagnostics. Do not silently drop roads, rename an area complete, or treat an area benchmark as a full county. Extrapolation to all 3,235 county-equivalents remains uncertain until representative dense, rural, geographically large, island, and cross-boundary cases and source availability are measured; no national job starts from this benchmark tool.

The counts-only preflight completed successfully in 241.45 seconds for both areas combined. Providence has 12,901 visible source ways, including 2,328 named ways and 947 distinct names, one base sheet, and 26 historical public-place records. The Washington scope has 4,660 visible source ways, including 889 named ways and 535 distinct names, eight base sheets, and three historical public-place records. Their selected polygon areas are 5.372 km² and 72.439 km², respectively; base sheets include useful edge context. The selected OSM settlement nodes Providence (`n158811904`) and West Kingston (`n158859649`) lie inside their respective pinned 2020 ZCTA polygons. These source-backed area names identify the leaves. No Census population or current USPS locality claim is inferred. Actual road/name coverage, PDF pages, memory, and timings still require the render benchmark.

## What the benchmark does and does not establish about ETA

The renderer can now produce useful selected county/area files from configuration. Input preparation took about 110 seconds for either area, while dense rendering cost more than the rural comparison. State-wide source traversal and repeated input preparation therefore need to be included in future forecasts; page count alone is insufficient.

A geometry-only check of the cached Rhode Island counties at the fixed trial scale finds 9 base sheets for Bristol, 34 for Kent, 56 for Newport, 68 for Providence, and 94 for Washington, before street insets. The current 64-page base guard rejects Newport, Providence, and Washington. Newport’s guard is conservative because it counts the larger rectangular candidate grid before filtering empty cells. This diagnostic raised only its local counting limit to enumerate sheets; it changed no production policy, rendered no additional PDFs, and started no national job.

These area measurements do not validate a three-minute full-county assumption or a national calendar ETA. Full county grouping, useful scale choices, necessary splits, source availability across states/territories, PDF complexity, and phone testing remain unmeasured. Blindly multiplying an area’s time by the county count would hide those costs. The next useful engineering step is a deterministic complete-county file plan with measured limits, rather than a national render queue over the current Bristol policy.

The generalized selector currently admits only the pinned Rhode Island input set and rejects other states or mismatched county IDs before reading sources. It is not a national source selector. A narrow follow-up guard and its regressions preserve this boundary after the frozen `565be7c` benchmarks; those PDFs retain their actual historical producer, without a new recipe label. National use also needs explicit county-vintage reconciliation before joining 2020 ZCTA relationships to changed county-equivalent systems.

Final source guard `ce8f715` passes 55 focused checks and Ruff. The benchmark producer remains exactly `565be7c`; no output is assigned the follow-up source recipe. The generated third-party attribution includes the new held Census input. A fresh generated release-review draft is retained locally, but is not copied over the tracked report because the generator drops its manually adopted security-requirements section; the integrator must preserve that section while incorporating this new held input.
