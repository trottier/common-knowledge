# Bounded county renderer benchmarks

The county prototype accepts an explicit policy file. Its default remains one full county per detailed PDF. State, county, and area names drive actual folder paths, PDF titles, headings, and bookmark checks. Selected policy bytes enter the recipe; unrelated county configurations do not. Every selected source-named way still needs a visible label, including bounded larger-scale insets. Existing Bristol artifacts remain unchanged under their original recipes.

The initial additional benchmarks use the existing Rhode Island source set: Census 2025 county boundaries, Geofabrik 2026-10-29 roads, the pinned 2026-10-30 Rhode Island PMTiles, the original incomplete Rhode Island directory, existing fonts, and epoch `1793404800`. The reused directory remains `complete: false`; rerendering does not add missing records or clear any review hold.

Only three Bristol ZIP geometries were cached. One bounded, unsimplified official [Census 2020 TIGERweb layer 84](https://tigerweb.geo.census.gov/arcgis/rest/services/Census2020/tigerWMS_Census2020/MapServer/84?f=pjson) query adds ZCTAs 02892 and 02903 from that same already selected vintage. Its response is 133,681 bytes, SHA-256 `15a1e41af65d9e0bb0d83c1e56bbea49df5ee3110ad3e505b05c2c8ffea6274f`. It is a held build input, not a new upstream release or national cargo. Its release date, review, and advisory/age gates remain unconfirmed. Census ZCTAs are dated statistical approximations, [not current USPS delivery boundaries](https://www.census.gov/programs-surveys/geography/guidance/geo-areas/zctas.html).

Two area policies provide bounded density comparisons: Providence County intersected with 2020 ZCTA 02903, then Washington County intersected with 2020 ZCTA 02892. These are explicitly partial-county benchmark scopes, not a claim that a production county must split or that the whole county is complete. Polygon intersection preserves the county as the maximum group; the original one-to-many county relationship data remains unchanged. Only source-verified ZIP codes appear in names. No population dataset or invented postal coverage is introduced; road density is measured from the selected source.

Each benchmark first runs `tools/prototype_county_map.py --counts-only --policy <selected JSON>` with authenticated inputs. It then renders one area at a time under one CPU and 4 GiB, using the pinned image, no network, read-only source/cache/input mounts, and a fresh output. The selected engineering trials retain 1:25,000 base scale, 190 × 230 mm map frames, 10% overlap, 64 total pages, maximum inset depth 5, source-way/vertex/tile guards, and the shared 10 MB PDF guardrail. These are explicit trial settings, not publisher defaults or phone acceptance evidence.

Record actual elapsed time, cgroup/RSS peak, exit and OOM state, source-way/name counts, base/inset/actual PDF pages, bytes, missing IDs, and actual map-region visual evidence. A page, coverage, or byte failure remains a failure with preserved diagnostics. Do not silently drop roads, rename an area complete, or treat an area benchmark as a full county. Extrapolation to all 3,235 county-equivalents remains uncertain until representative dense, rural, geographically large, island, and cross-boundary cases and source availability are measured; no national job starts from this benchmark tool.
