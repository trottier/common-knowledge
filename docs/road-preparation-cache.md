# Verified state road preparation cache

The optional road cache replaces repeated PBF traversal with a local SQLite/RTree query. The direct PBF path remains available. Both share the same source filter, full-precision projected geometry, exact viewport intersection, attribute selection, ordering, and selected-way guard. No road geometry is simplified.

`tools/prepare_road_cache.py` reads one pinned source and the existing configured road classes. It writes `files/roads.sqlite`, deterministic source/filter/environment bindings and counts, and a standard generated manifest. It downloads nothing. Cache creation requires a fresh output. Failed or partial directories lack the required pinned complete manifest and cannot be admitted.

The cache is bound to the selected source attributes and hash, allowed road/place classes, excluded-tag data and function, shared extraction/cache producer, exact environment sources and tool versions, and projected CRS. It does not consume county templates, ZIP geometry, or unrelated catalog records. Human review notes remain separate gates. A cache is admitted only after its actual generated catalog pin `road_cache_ri` exists; a self-declared database hash is insufficient. The normal generated-input checks authenticate its manifest, source pins, SQLite bytes, audit files, completeness, epoch, and producer/filter/CRS binding.

The consumer opens the verified database read-only and immutable. Producers must mount the cache read-only and keep it frozen. SQLite’s [documented RTree overlap behavior](https://sqlite.org/rtree.html#roundoff_error) rounds stored bounds outward, which may add candidates but does not omit an overlapping rectangle. Full-precision WKB geometry and the same exact intersection as the direct path determine the final roads. The [read-only URI mode](https://sqlite.org/uri.html) and immutable database assumption apply only to the frozen, checksum-verified artifact.

`read_cached_roads(root, catalog, folder, extent, allowed, crs, maximum, epoch, selection_allowed=None)` returns roads, sorted settlements, class counts, and its admitted manifest. Roads retain `id`, `kind`, `name`, `ref`, `access`, and clipped GeoJSON geometry. Display selection can be a subset of the cache’s source classes, such as the existing overview road classes, but cannot request uncached classes. Filtering happens before the selected-way guard; detail defaults still require every selected source-named way.

`tools/prototype_county_map.py --road-cache <prepared cache>` activates this optional path. The current county proof admits only the existing Rhode Island source set. The cache is a build input, not shipped map cargo, a complete county, or a source/rights/release approval. Actual timings and equality evidence are recorded separately after bounded comparisons; no national performance or fit claim follows from the Rhode Island cache.

For a frozen whole-county plan, the library `prepare(..., planned_part=part)` accepts a projected part record with `id`, `area_name`, `county`, `crs`, `geometry`, verified `zctas`, and the authenticated whole-plan `plan_sha256`. The caller verifies that plan receipt before passing it. The renderer checks county/CRS containment, exact ZIP intersections, and source counts, and includes the complete part record in its producer fingerprint/provenance. Residual parts can have no ZIP codes and receive no fabricated suffix. A ZIP label is moved to a representative point of its displayed intersection when the source interior point falls outside a planned part; original geometry remains unchanged. Root integration retains one whole-county overview rather than overwriting it with individual part overviews. Actual intersecting base sheets consume the unchanged page cap; optional `max_candidate_cells` is an independent planning-work guard.


## Measured Rhode Island proof

Frozen producer `9f60acd` built 133,842 accepted ways and 109 settlements into a 37,613,568-byte SQLite file in 136.66 seconds of host wall time. Its measured cgroup peak was 479,199,232 bytes, with exit 0 and no OOM events. The generated item is `road_cache_ri`, canonical manifest SHA-256 `9e5a66a1d13527c7095611a588e728e4dce03cb6c127c6334a878f41b2aa38a7`.

The fully authenticated Kent query took 1.733 seconds and returned 30,519 ways, including 9,512 named ways and 5,298 distinct names, plus 18 settlements. Canonical IDs, names, attributes, every geometry coordinate, ordering, and class counts exactly match the independently prepared direct Kent scene. Through the newly built installed wheel, the same query took 1.671 seconds and produced the identical cached-row file hash. It imported the new module from the installed target, while still resolving source resources from the explicit project root.

A matched Providence viewport comparison measured the exact historical `565be7c` direct extractor at 108.909 seconds and admitted cache reuse at 0.783 seconds, under one CPU and the same pinned image. All 12,901 ways, including 2,328 named ways and 947 distinct names, have identical full canonical results. The roughly 139-fold ratio applies only to this measured road-selection stage; it is not an end-to-end PDF, cold-device, national, or phone speed claim.

The [evidence receipt](evidence/ri-road-cache-2026-11-01.json) records exact bindings, hashes, execution states, source and installed-module comparisons, and retained review limits. Seventy focused checks and Ruff pass. A tiny synthetic fixture’s repeated cache bytes match; the real cache has one measured build, so no full-cache A/B claim is made. Source/cache mounts remained read-only, and no archived content, dependencies, or source versions were fetched or changed.
